## 目的と適用範囲

タイムライン上で「表示範囲を移動する」「クリップを選ぶ・編集する」「再生位置を指定する」を区別し、After Effectsに慣れた利用者が同じ操作を使えるようにする。優先するのは、マウスの移動・ズーム、意図しない編集の防止、フレーム単位での位置合わせである。

DualViewのA/B比較用トラックとクリップ構造を維持する。After Effectsのレイヤー構造、プロパティ階層、グラフエディターを再現する計画ではない。操作の変更は既存プロジェクトにも適用するが、保存済みのクリップ位置、素材範囲、速度、逆再生、キーフレームを変換しない。

この計画はコードと公式資料に基づく。現行アプリとAfter Effectsを並べた実操作確認、マウスやトラックパッド別の感触、長時間素材での応答時間は未検証であり、実機比較は2026-11-04の利用者の決定により、利用者がマージ前に確認する。

## 操作仕様の提案

### 表示範囲と再生位置

| 入力                           | 改善後の動作                                                         |
| ------------------------------ | -------------------------------------------------------------------- |
| ホイール                       | トラックの上下移動。トラック名と内容がずれないようにする             |
| Shift＋ホイール                | 時間方向の左右移動。ホイールを奥へ回すと過去、手前へ回すと未来へ進む |
| Alt＋ホイール                  | ポインターの時刻を保って拡大・縮小。前方回転で拡大                   |
| 中ボタンのドラッグ             | 手のひら操作で表示範囲を移動。クリップ上でも編集を始めない           |
| Spaceを押しながら左ドラッグ    | 一時的に手のひら操作。短押しは再生・停止                             |
| H / V                          | タイムラインの手のひら操作 / 選択操作に切り替える                    |
| 時間定規のクリック・左ドラッグ | その時刻へ移動し、ドラッグ中もフレームを確認する                     |
| 再生位置の頭部分のドラッグ     | 定規と同じシーク。トラック上の縦線はクリップ操作を遮らない           |
| トラックの空白をクリック       | 選択解除。再生位置は変更しない                                       |
| 差分帯のクリック               | 既存どおり差分時刻へ移動。囲み選択を始めない                         |
| `=` / `-`                      | 再生位置を基準に時間方向の拡大・縮小                                 |
| `;`                            | 1フレームを見分けられる拡大表示と全区間表示を切り替える              |
| Shift＋`;`                     | 全区間表示と直前の表示範囲を切り替える                               |
| D                              | 再生位置が画面外にある場合、その付近まで表示を移動する               |

ホイール・手のひら操作の基準は[Adobeのインターフェース資料](https://helpx.adobe.com/after-effects/desktop/get-started/get-familiar-with-the-interface/general-user-interface-items.html)。資料が時間定規上の操作として説明するAlt・Shiftホイールは、DualViewではトラック領域にも適用する。

Spaceは用途が重なるため、タイムライン内では押下時に保留し、ドラッグしなかった場合だけキーを離した時に再生を切り替える。これはブラウザーで操作を両立するための適用仕様であり、After Effectsと再生開始のタイミングまで同一とはしない。キーを押し続けた際の反復では連続切替を起こさず、手のひら操作に使ったSpaceを離しても再生しない。

### 選択・移動・トリム

- 通常クリックで単一選択へ置き換える。Ctrl＋クリックでは追加・解除する。macOSではCtrlをCommandへ読み替える。
- Shift＋クリックで選択範囲を広げる。DualViewでの順序は、表示トラック順、同一トラック内の開始時刻順、同時刻は現在の表示順とする。この順序はクリップ型タイムラインへの適用案であり、After Effectsのレイヤー順との完全一致を主張しない。
- 空白の囲み選択はDualViewの便利な操作として残す。Shift付きは既存選択へ追加し、通常の囲み選択は置き換える。ロックされたトラックを編集対象へ追加しない。
- 選択済みクリップを押した時点では複数選択を維持し、移動のしきい値を超えたら選択全体を同じ時間差で移動する。クリックで終わった場合だけ単一選択へ絞る。修飾キー付き選択ではドラッグを開始しない。
- 複数クリップの移動は各トラックを保つ。単一クリップは従来どおりA/B等の別トラックへ移せるが、実際の行位置で移動先を判定し、ロック・素材種別の制約を守る。複数クリップの縦移動は今回扱わない。
- 端を左ドラッグすると、そのクリップをフレーム単位でトリムする。複数クリップの同時トリムは今回扱わない。
- 通常はフレーム境界にだけ合わせ、Shift中に時刻の吸着を有効にする。移動中は先頭・末尾の両方、トリム中は操作中の端、シーク中は再生位置を基準にする。
- 吸着先は0秒、区間末尾、他クリップの端、マーカー、ループ端、再生位置とする。移動対象自身を除外し、再生位置を動かす際は元の再生位置を候補にしない。画面上10px以内の最も近い候補を採用し、同距離では再生位置、マーカー、クリップ端、その他の順とする。候補はタイムラインのフレーム境界へそろえる。
- `snapEnabled`はShift吸着を許可する設定として保持し、標準値はtrueとする。旧`snapThreshold`の読み書きを維持するが、マウスの吸着距離は既存の`getZoomAwareSnapThreshold`相当の10pxで判定する。Nキーの常時吸着切替は廃止し、ボタンにはShift操作を説明する。
- 移動・トリムは一時表示を経てボタンを離した時に確定する。確定した編集一回につき履歴を一件追加する。クリック、移動量ゼロ、制約による拒否、Escape取消は履歴・やり直しを変えない。
- Escape、`pointercancel`、ポインター捕捉の喪失、ウィンドウの失焦では未確定の移動・トリム・囲み選択を取り消す。シークは最後に指定した再生位置で止め、手のひら操作は現在の表示位置で止める。同じEscapeをループ解除等へ流さない。

[Adobeのマーカー資料](https://helpx.adobe.com/after-effects/desktop/work-with-layers/work-with-layer-and-composition-markers/layer-markers-composition-markers.html)はShiftドラッグによる時刻吸着を説明している。囲み選択や複数クリップのトラック保持は、DualViewに合わせた仕様である。

### キーとパネルの優先順位

タイムラインをクリック、またはTabで移動して操作対象にした場合、そのパネルがキーを所有する。テキスト入力、日本語変換、ダイアログ・メニュー、スライダーの既存除外を維持する。入力欄からタイムライン本体をクリックした場合は、入力内容を保って焦点をタイムラインへ移す。

| キー                                        | タイムラインが操作対象のとき                                                           |
| ------------------------------------------- | -------------------------------------------------------------------------------------- |
| PageUp / PageDown、Ctrl＋左右               | 前後1フレーム                                                                          |
| Shift＋PageUp / PageDown、Ctrl＋Shift＋左右 | 前後10フレーム                                                                         |
| Home / End                                  | 先頭 / 最終表示フレーム                                                                |
| I / O                                       | 選択クリップの最初 / 最後の表示フレーム。複数選択は最も早い先頭 / 最も遅い末尾         |
| B / N                                       | ループ範囲の開始 / 終了を現在フレームに合わせる                                        |
| J / K                                       | 現在時刻より前 / 後の表示中のマーカー・ループ端へ移動。該当なしなら動かさない          |
| `[` / `]`                                   | 選択クリップの先頭 / 最後の表示フレームを現在フレームへ移動                            |
| Alt＋`[` / Alt＋`]`                         | 選択クリップの先頭 / 最後の表示フレームを現在フレームでトリム                          |
| Ctrl＋Shift＋D                              | 現在位置で選択クリップを分割。未選択なら現在位置をまたぐロック外のクリップを対象とする |
| F2                                          | 選択解除                                                                               |
| Delete、Ctrl＋A、Ctrl＋Z、Ctrl＋Shift＋Z    | 削除、全選択、取り消し、やり直し                                                       |
| Ctrl＋D / Ctrl＋C / Ctrl＋V                 | 現行の複製・コピー・貼り付けを維持。配置規則は下記の差を明記する                       |

キーは[Adobeの標準ショートカット](https://helpx.adobe.com/after-effects/desktop/get-started/keyboard-shortcuts/keyboard-shortcuts-reference.html)、フレーム移動と再生停止は[Adobeのプレビュー資料](https://helpx.adobe.com/after-effects/desktop/view-and-preview/preview-video-and-audio/previewing.html)を基準にする。パネルをクリックした後にも比較モードのHや音声QAのBが割り込む現状を解消する。

タイムラインにはキーフレーム行がないため、J/Kで非表示のキーフレームへ移動しない。通常の定規ドラッグは再生を停止してシークし、Alt付きでは再生を維持する。シーク要求には`usePlaybackStore`を使い、A/Bに別々の再生時計を作らない。

通常Sの分割、Q/Wの片側削除、Rのリップル切替、I/Oのループ指定、Bのサイドバー切替、Tのタイムライン非表示、J/K/Lの変速再生をタイムライン内の割り当てから外す。対応するAfter Effectsの機能をまだ持たない文字キーは、破壊的な別操作へ転用しない。比較画面を操作対象に戻した場合は、既存の比較・変速再生等のキーを引き続き利用できる。

ブラウザー全体のCtrl＋`+`/`-`は奪わず、時間方向のズームを`=`/`-`へ移す。Ctrl＋Sと履歴操作、比較モードの切替、ヘルプは共通操作として残す。日本語配列で記号キーの位置が異なるため、`KeyboardEvent.key`による記号と`code`による物理キーを混同しない。

## 互換性と残る違い

- `.dualview`のバージョン1/2、素材参照・再接続、自動保存を維持する。新しい操作設定形式や版番号は作らない。
- 内部のクリップとループの終了時刻は「その時刻を含まない」。After Effects風の末尾フレーム指定は境界で変換する。30fpsの`[0, 1)`のクリップではOは`29/30`秒、そこでAlt＋`]`やNを押した場合の保存用終了境界は1秒になる。`splitClip`の位置には1フレームを加えない。
- この終了境界の扱いは新しい入力操作に適用する。旧プロジェクトの`endTime`、`outPoint`、ループ端を一律に1フレームずらさない。
- キーフレーム付きクリップの先頭トリム・分割を拒否する既存制約を維持し、理由を既存の編集メッセージに表示する。入力の変更と同時にアニメーション編集の制約を解除しない。
- 移動時は素材のin/out、速度、逆再生、キーフレームのローカル時刻、選択クリップ間の時間差を維持する。編集不可能な対象を含む一括編集は全体を拒否して理由を表示し、部分確定しない。
- After Effectsの同時刻・別レイヤーへの複製は採用しない。現行の「同トラックで直後へ複製」「再生位置へ貼り付け」を維持する。重なりによるA/Bの表示素材の選択まで変えるため、同時刻複製は別の設計判断とする。[Adobeのレイヤー操作資料](https://helpx.adobe.com/after-effects/desktop/work-with-layers/select-and-arrange-layers/selecting-arranging-layers.html)との違いとして操作ガイドに記載する。
- ループ範囲はAfter Effectsのワークエリアに対応させるが、書き出し区間やコンポジション長の変更までは連動させない。
- パン・スクロール・操作途中の状態は取り消し履歴の対象や素材保存の対象にしない。ズームは現行どおり保存する。スクロール位置、H/V、Spaceの押下状態を新たにプロジェクトへ保存しない。

## 実装する順序

### 1. 入力の所有と座標計算を整える

`Timeline.tsx`に焦点を持てるパネル領域と表示中の操作種別を設ける。操作は手のひら、定規、クリップ端、クリップ本体、空白の順に判定し、一回の押下で複数の操作を始めない。右ボタンは既存メニュー、中ボタンは手のひらに限定する。

`createShortcutDispatcher`にタイムラインが操作対象かを判断する分岐を追加する。必要なら`viewer`の範囲を一つ追加し、`App.tsx`の共通操作と比較画面用操作を分ける。新しい入力配信基盤や利用者向けのキー設定画面は作らない。

座標の計算は`src/lib/timeline/interaction.ts`へ、複数の呼び出し元が使う計算だけをまとめる。横座標はスクロール後の内容座標を使い、ドラッグ開始後のスクロール差も反映する。縦の対象判定は実際のトラックの矩形を使い、64/58の固定値に依存しない。

既存のマウス処理を`PointerEvent`と捕捉へ移し、開始・確定・取消を所有する要素を明確にする。捕捉方法は[MDNのsetPointerCapture](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture)を参照する。既存のフックの責務を維持し、汎用ジェスチャーライブラリーを追加しない。

検証: `pnpm typecheck`、`pnpm exec playwright test e2e/keyboard-context.e2e.ts e2e/timeline-interactions.e2e.ts --retries=0`。入力・変換・メニューの保護とボタン別の操作開始が成功すること。

### 2. パン・ズーム・定規を実装する

`useTimelineViewport.ts`にタイムライン専用の表示範囲操作を置き、ボタン、ホイール、キーが同じ拡縮計算を使うようにする。ズーム前にポインターの時刻を求め、更新後も同じ画面位置へ戻す。端で制限される場合を除き、誤差は1px以内とする。

全区間表示に必要な倍率まで縮小でき、1フレームを見分けられる倍率まで拡大できるよう、固定の最小・最大倍率を見直す。`;`の拡大時には1フレーム12pxを目安とし、再生位置を画面内へ表示する。`timeMarkers`は表示範囲と前後の余白に必要な分だけ生成し、高倍率ではフレームの整数倍で目盛りを刻む。素材ごとのfpsや再生時計の設計を変更しない。

縦スクロールではラベルとトラックを同時に動かし、定規・差分帯を上部に保つ。横スクロールは時間領域だけを動かす。差分帯のクリックと既存の素材D&Dを維持する。

ホイールは`deltaMode`を正規化し、トラックパッドの横入力を二重変換しない。Ctrl付きのピンチ入力をAltホイールへ誤認しない。タイムラインが処理する入力だけを止める。詳細は[MDNのwheelイベント](https://developer.mozilla.org/en-US/docs/Web/API/Element/wheel_event)を参照する。

検証: `pnpm exec vitest run src/lib/timeline/interaction.test.ts`、`pnpm exec playwright test e2e/timeline-interactions.e2e.ts e2e/timeline-diff.e2e.ts --retries=0`。パンで編集・選択・再生位置が変わらず、ズームの時刻保持、スクロール後のシーク、全区間表示が成功すること。

### 3. 選択と編集の確定・取消を実装する

`selectedClipIds`を選択集合、`selectedClipId`をその中の主対象として整合させる。新しい選択用ストアは作らない。単一選択、追加・解除、範囲、囲み、右クリックの選択方針を同じ規則へそろえる。選択内で右クリックした場合は集合を維持し、選択外では対象だけへ置き換える。

`useTimelineDrag`に選択全体の移動プレビューを持たせる。複数移動にはストア内で対象と制約を確認して一度に更新する操作を用意し、一部だけの更新を避ける。全クリップに共通の移動量をフレーム単位で求め、先頭0秒の制限でも相対時間差を崩さない。

トリムの制約計算はプレビューと確定で共有し、`trimClip`が保証する速度・逆再生・素材端・最小1フレーム・リップル・既存キーフレーム制限を保つ。`mousemove`ごとに保存対象のトラックを変更する方式を、表示だけのプレビューと解放時の確定へ置き換える。履歴は有効な確定時だけ`runWithHistory`で記録する。

`useEdgeAutoScroll`で表示範囲が移動した場合、マウスが静止していても内容座標とプレビューを更新する。`pointerup`でも最後の座標を評価し、直前のReact再描画を確定条件にしない。

検証: `pnpm exec vitest run src/stores/timelineStore.test.ts src/stores/autosave.test.ts src/lib/timeline/interaction.test.ts`、`pnpm exec playwright test e2e/timeline-interactions.e2e.ts e2e/clip-editing.e2e.ts --retries=0`。移動・トリム各一回を一回の取り消しで戻せ、取消・拒否・移動量ゼロではやり直しが残ること。

### 4. キーをそろえ、説明と既存試験を更新する

操作仕様表のキーをタイムライン範囲に実装し、`App.tsx`や比較モードに古い入力が漏れないようにする。B/NとI/Oの役割を交換し、フレームの終了境界を共通の変換処理で扱う。Spaceのkeyupは、このパネルで押下を受理した場合だけ処理し、失焦時には保留を消す。

`ClipContextMenu`、ボタンの説明、`KeyboardShortcutsHelp`、日英README・利用ガイドを同じ変更で更新する。旧キーを押していたブラウザー試験は、新しい操作対象とキーを明示するよう更新し、素材時刻・画素・保存復元の期待値を弱めない。

検証: `pnpm exec playwright test e2e/keyboard-context.e2e.ts e2e/clip-editing.e2e.ts e2e/playback-clock.e2e.ts e2e/difference-regions.e2e.ts e2e/timeline-interactions.e2e.ts --retries=0`。タイムラインと比較画面を切り替えても、各キーが一つの処理だけを実行すること。

### 5. 全体検証を終え、After Effectsとの実操作比較を引き継ぐ

下記の共通検査と全ブラウザー試験を実施する。通常動画とProResをA/Bに配置し、移動・トリム・シーク後に同じフレームを比較できることを実画素で確認する。バージョン1/2の再読み込み、参照素材の再接続、編集の自動保存を確認する。

利用者のマージ前確認ではWindows版After Effectsの初期設定と並べ、ホイール、Shift/Altホイール、中ボタン、Space、定規、Shift吸着、PageUp/Down、I/O、B/Nを比較する。Shift範囲選択と記号キーは公式資料だけで詳細が確定しなかったため、日本語配列を含む実機で確認し、差があれば該当仕様を更新する。macOSを実機確認していない場合は、その範囲を確認済みと報告しない。

## 試験の具体例と合格条件

新しいブラウザー試験は`e2e/keyboard-context.e2e.ts`の準備方法と`e2e/mediaPlayback.ts`の素材・画素確認を参考にし、対象操作には実際のマウスとキーを使う。ストアへの直接設定は試験準備と結果観測に限定する。

| 検証対象             | 独立した期待結果の例                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------ |
| 単一選択への置換     | A/Bを選択後にCをクリックしDeleteすると、Cだけが消えA/Bが残る                                     |
| 一括移動             | `[1,3)`と`[4,5)`を2秒移動すると`[3,5)`と`[6,7)`になり、素材範囲・速度・キーフレームは同じ        |
| 移動量の制限         | 上記を3秒前へ動かそうとすると共通差分は-1秒となり、時間差3秒を保つ                               |
| 取消と履歴           | 取り消した後にドラッグ・トリムを取り消しても、元のやり直しで同じ編集を復元できる                 |
| フレームの末尾       | 30fpsの`[0,1)`はOで`29/30`秒へ移動。Alt＋`]`による終了境界は1秒                                  |
| 最寄りの吸着         | 1秒と1.08秒が候補で1.07秒へ動かすと、Shift中だけ1.08秒を選ぶ。対象自身の端は選ばない             |
| 倍率に依存しない吸着 | 異なる倍率で候補との画面距離を同じにし、10pxの内側・外側で同じ吸着可否になる                     |
| 自動スクロール       | 端でマウスを止めてもプレビューが表示の移動に追従し、確定位置が最後の内容座標と一致する           |
| パンと再生           | クリップ上の中ドラッグ・Spaceドラッグで位置と選択と再生位置が変わらない。Space短押しだけ再生する |
| パネルの分離         | 音声QA表示中でも、タイムラインのBはループ開始、比較画面のBは音声Bだけを選ぶ                      |
| 入力の保護           | 入力中・変換中・ダイアログ内のキーでクリップ、範囲、再生状態が変わらない                         |
| 保存と素材           | 編集後の保存・再読込・再接続後にもクリップとキーフレーム、およびA/Bの表示画素が一致する          |

## 実装記録（2026-11-04）

入力の取り扱いを`useTimelineViewport`、キーの割り当てを`useTimelineKeys`へまとめた。新しい計算専用モジュールは増やさず、共有するトリム制約・吸着計算は既存ストアの処理を再利用した。古い比較画面のショートカットは比較画面を選んだ場合に維持する。

計画のAfter Effects実機比較、日本語配列での記号キー、実際のトラックパッドでの操作感は未確認である。自動試験の成功と実機での確認を同一視しない。素材デコードや40GB素材の性能値は今回測定していない。

独立レビューで見つかったトラック設定・追加メニューの切り取りと、画面外の再生位置を基準にできないズームを修正した。キーボードによる複数トリムは元の配置から一括計算し、リップル編集で選択対象を途中移動させない。起動時のStrictMode二重初期化が素材を破棄する競合は、解除済み処理の新規プロジェクト作成を抑止して解消する。

選択クリップ同士が同一トラックで重なる一括リップルトリムは、短縮量の二重計上を避けるため編集前に全体を拒否し、個別編集を案内する。通常の重なり配置やリップルを無効にしたトリムは維持する。
