# 音声処理の常駐メモリーを同条件で採取する

#77 の測定基盤です。製品コードを変更しない通常の本番ビルドを使います。
音声結果の画面表示を実 UI で待ち、ブラウザー専用プロセス群の常駐量を Linux の
`ps` で採取します。#73 の呼出し観測付き取消診断とは別の系列です。

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install --with-deps chromium
node e2e/diagnostics/production-memory.mjs test-results/audio-memory-1
```

Node / pnpm はリポジトリ指定版を使用します。Linux と procps の `ps` が必要です。
既存の保存先を上書きしません。対応する Chromium を既に用意している場合のみ
`BROWSER_EXECUTABLE_PATH` を指定できます。サンドボックスは常に有効です。
ポート4179で専用サーバーを起動し、各試行に専用ブラウザーを新しく起動します。
各ブラウザーはページ1枚だけで、普段のプロファイルやユーザー素材を使いません。

## 固定する条件

既存の `audio-long.webm`（120秒・48kHz・逆相ステレオOpus）を A/B に読み込みます。
通常→DevTools 4倍 CPU 制限の順を3回反復し、計6試行を再試行なしで保存します。
ProRes、入力上限に近い素材、実機低性能端末はこの系列では未測定です。
4倍制限は外部 CPU 負荷を発生させる方法と同一ではありません。

他のビルド・ブラウザー試験を止め、同じ端末と固定依存関係で実行してください。
試行前後の平均負荷を保存しますが、共有ホストや電源・割当の統制を証明する値では
ありません。全体の試行制限60秒を超えた場合も失敗を残します。制限値は性能の
合格基準ではなく、通るまでの再試行や制限延長は行いません。

## 観測区間

素材読込後に採取を開始し、音声入場前・A/B結果が表示されるまで・結果表示後・
Slider退出後を分離します。入場前・完了後・退出後は各1秒の観測窓を設けます。
これは回収を強制する時間でも、一定時間後にメモリーが戻るという契約でもありません。
強制GC、トレース、動画記録、画面撮影、ページ内の呼出し観測は行いません。
結果表示の待機・操作に必要な Playwright の観測負荷はあります。

採取の開始・終了と区間遷移は試験ドライバーの単一時計です。ブラウザー内の抽出・
解析境界や物理表示完了を直接計測するものではありません。区間変更をまたぐ標本は
生記録と全体最大値には残し、区間別集計から除外します。欠測や区間内の標本不足をゼロにしません。

## 指標の範囲と限界

`ps -e -o pid=,ppid=,rss=` の KiB をバイトへ換算し、専用ブラウザーの親PIDと
その時点の子孫プロセスだけを合計します。Node、Vite、別ブラウザーは含みません。
100msは前の採取完了から次の開始までの予約時間であり、保証された標本間隔では
ありません。実際の開始・終了時刻、PID別の生値、採取エラーを保存します。

この合計RSSは共有ページを重複計上します。採取中にプロセスが変わる場合、短命や
親が変わったプロセス、標本間の瞬間的な最大値、プロセス外のGPU・ドライバー資源を
網羅できません。プロセス全体を完全に同時に採取する方法でもありません。
したがって「観測されたRSS最大値」であり、厳密な物理メモリー最大値ではありません。
JavaScriptヒープ、PCMの理論量、OS全体の使用量とも別の指標です。

退出後のRSSが高いという値だけで解放漏れと断定しません。解放の所有権とOS回収は
別であり、ブラウザーやOSの確保済み領域・キャッシュが残ることがあります。

## 記録と判定

`plan.json` に試行順序、対象SHA、未コミット状態、素材・固定依存関係・実行コードの
ハッシュ、環境と測定の限界を保存します。`results.json` に実ブラウザー版、
試行前後の負荷、全標本、段階ごとの最大・最小RSS、エラーを残します。
条件別に各試行の観測最大値の全生値、件数・欠測・最小値・中央値・最大値を集計します。
3試行から上位分位や上限保証は推定しません。無効試行があれば非ゼロ終了します。

計測基盤だけの統合では #77 を閉じません。代表端末・素材・許容量の合意、同条件の
比較と必要素材の実測が残っています。製品修正のない比較で削減率を主張しません。
通常品質検査と対象先端のCIも、この計測で代用しません。
